## 📝 Deskripsi Repository
Repositori ini difungsikan sebagai arsip komprehensif untuk seluruh rangkaian kegiatan Day 1 Proyek Workshop. Cakupan materinya meliputi orientasi akademik Jurusan TIK, sosialisasi program MBKM (Studi Independen, PBL, Magang), hingga praktik teknis *version control* dan *Prompt Engineering*.

## 🎯 Tujuan
- Mendokumentasikan *knowledge base* dari materi *workshop* secara terstruktur.
- Menjadi *log* pembelajaran pribadi terkait optimasi perintah AI dan manajemen *source code*.
- Menjadi bukti implementasi nyata alur *Version Control System* (VCS): `git init` ➔ `git add` ➔ `git commit` ➔ `git push`.
- Memenuhi parameter evaluasi dan *requirement* tugas dari panitia Proyek Workshop.

## 📖 Rangkuman Kegiatan
1. **Orientasi Akademik TIK (Bpk. Hatta)**
   Pemaparan visi JTIK sebagai entitas pendidikan vokasi bertaraf internasional yang berfokus pada riset, inovasi, dan tata kelola digital. Ekosistem ini didukung oleh kemitraan strategis dengan industri besar seperti Huawei, Agate, dan Pemkot Depok.
   
2. **Sosialisasi MBKM, PBL & Magang (Bu Euis & Bu Maria)**
   Penjelasan skema konversi SKS melalui program MSIB (Magang dan Studi Independen Bersertifikat) di bawah payung Kurikulum Merdeka. Kunci utamanya adalah perencanaan awal: pemetaan minat, konsultasi rutin dengan Dosen, serta kedisiplinan membangun portofolio, CV, dan dokumentasi proyek.

3. **Building with AI & Git/GitHub (Nugi Farhan)**
   - **Prompt Engineering:** Strategi memanipulasi model AI menggunakan parameter *Role, Task, Context, dan Format* agar *output* presisi dan terarah.
   - **VCS Lifecycle:** Demistifikasi perbedaan Git (mesin pelacak lokal) dan GitHub (platform kolaborasi *cloud*). 
   - **Praktikum:** Melakukan *scaffolding* kode aplikasi *Student Task Planner* menggunakan AI, lalu mendistribusikannya ke *repository* GitHub.

## 💡 Poin Penting & Pengetahuan Baru
- Menyuntikkan konteks spesifik pada *prompt* akan menekan tingkat halusinasi AI, namun validasi *output* secara manual tetap berstatus wajib bagi seorang *engineer*.
- Membedakan *environment* lokal dan *remote*: perubahan *file* tidak bisa langsung dikirim ke GitHub tanpa melewati fase *staged* (`add`) dan *committed* di Git lokal.
- Konversi SKS melalui MBKM bukan proses instan; kelayakannya sangat bergantung pada seberapa awal mahasiswa merencanakan dan menyusun rekam jejak teknis (portofolio).

## 💭 Pendapat Pribadi & Evaluasi
Rangkaian acara Day 1 sangat krusial dan relevan. Sesi pengenalan akademik memberikan *roadmap* karir yang jelas bagi mahasiswa, sementara materi *workshop* langsung membekali kami dengan dua *tools* yang wajib dikuasai di industri saat ini: AI dan Git. Komparasi langsung antara *prompt* mentah vs. terstruktur menjadi *highlight* yang sangat membuka wawasan. 

Namun, kurva pembelajaran paling menantang ada pada fase konfigurasi Git dan setup *SSH key*. Sebagai saran, panitia sebaiknya menyediakan modul *troubleshooting* atau *cheatsheet* instalasi tertulis sebelumnya, serta memperlebar porsi waktu untuk *hands-on practice* agar pemahaman peserta lebih merata.
